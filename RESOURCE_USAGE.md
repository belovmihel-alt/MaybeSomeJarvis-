# Анализ потребления ресурсов

## Сервер на основном ПК (desktop_server)

### 1. Потребление памяти (RAM)

#### В режиме ожидания (idle):
```
Flask приложение:     ~50-80 MB
Python интерпретатор: ~30-40 MB
Логирование:          ~5-10 MB
-----------------------------------
ИТОГО:                ~85-130 MB
```

#### При выполнении скрипта:
```
Базовое потребление:  ~85-130 MB
Временный процесс:    ~30-50 MB (на время выполнения)
Выходные данные:      ~1-10 MB (в памяти до 10KB ограничения)
История (100 записей): ~5-15 MB
-----------------------------------
ИТОГО PEAK:           ~120-200 MB
```

#### Факторы, влияющие на потребление памяти:
- **Количество одновременных запросов**: каждый запрос создает новый процесс
- **Размер выполняемого кода**: больше кода = больше памяти
- **Выходные данные**: ограничены 10000 символами (настраивается)
- **История выполнения**: ограничена 100 записями в памяти

#### Расчет для множественных запросов:
При 10 одновременных запросах:
```
Базовое:              ~130 MB
10 процессов:         ~500 MB (10 × 50 MB)
-----------------------------------
ИТОГО:                ~630 MB
```

**Рекомендация**: Для безопасности резервируйте **1-2 GB RAM** для сервера.

### 2. Потребление CPU

#### В режиме ожидания:
```
Flask + waitress:     0-1% CPU
Мониторинг:           <1% CPU
-----------------------------------
ИТОГО:                ~1-2% CPU
```

#### При выполнении скрипта:
```
Flask обработка:      5-10% CPU
Проверка безопасности: 1-2% CPU
Выполнение скрипта:   10-100% CPU (зависит от скрипта)
-----------------------------------
ИТОГО:                15-110% CPU (один запрос)
```

#### Типы нагрузки по командам:

**Легкие команды** (1-10% CPU):
- Вывод текста: `print("hello")`
- Простые вычисления: `2 + 2`
- Чтение переменных: `datetime.now()`

**Средние команды** (10-30% CPU):
- Работа с файлами: создание/чтение файлов
- Открытие браузера: `webbrowser.open()`
- Парсинг JSON/YAML

**Тяжелые команды** (30-100% CPU):
- Математические вычисления (факториал больших чисел)
- Обработка изображений
- Сетевые запросы с ожиданием

**Рекомендация**: Современный многоядерный процессор (4+ ядра) справится без проблем.

### 3. Потребление диска

#### Постоянное хранение:
```
Код сервера:          ~15 KB (server.py)
Конфигурация:         ~1 KB (config.yaml)
Зависимости:          ~5-10 MB (Flask, PyYAML)
Логи:                 ~1-100 MB (зависит от активности)
-----------------------------------
ИТОГО:                ~6-110 MB
```

#### Временные файлы:
```
Выполняемый скрипт:   ~1-10 KB (удаляется после выполнения)
Лог файл (server.log): растет со временем
```

**Рекомендация**:
- Минимум: **100 MB свободного места**
- Рекомендуется: **500 MB - 1 GB** для логов

#### Ротация логов:
Логи растут примерно:
- Низкая активность: ~1-5 MB/день
- Средняя активность: ~10-50 MB/день
- Высокая активность: ~100+ MB/день

**Решение**: Настройте ротацию логов (logrotate на Linux).

### 4. Сетевое потребление

#### На один запрос:
```
Входящие данные:
  - Заголовки HTTP:    ~0.5 KB
  - JSON запрос:       ~1-5 KB (код скрипта)
  -----------------------------------
  ИТОГО входящих:      ~1.5-5.5 KB

Исходящие данные:
  - Заголовки HTTP:    ~0.5 KB
  - JSON ответ:        ~0.5-10 KB (зависит от вывода)
  -----------------------------------
  ИТОГО исходящих:     ~1-10.5 KB

ОБЩИЙ ТРАФИК:          ~2.5-16 KB на запрос
```

#### Расчет трафика:
- 10 запросов/час: ~25-160 KB/час
- 100 запросов/день: ~0.25-1.6 MB/день
- 3000 запросов/месяц: ~7.5-48 MB/месяц

**Рекомендация**: Трафик минимален, ~50-100 MB/месяц достаточно.

### 5. Производительность и масштабируемость

#### Текущая конфигурация:
- **Режим**: threaded=True (многопоточный)
- **Одновременных запросов**: ограничено количеством потоков Python (~100-200)
- **Таймаут выполнения**: 30 секунд (настраивается)

#### Теоретическая пропускная способность:
```
Средняя команда:      ~2-5 секунд выполнения
Максимум потоков:     ~100-200
-----------------------------------
Запросов в секунду:   ~20-100 RPS (теоретически)
Реально:              ~5-20 RPS (практически)
```

#### Узкие места:
1. **subprocess.run**: блокирует выполнение на время скрипта
2. **GIL Python**: ограничивает параллелизм CPU-bound задач
3. **Временные файлы**: создание/удаление файлов на диске

#### Решения для масштабирования:
1. **Celery/RQ**: очередь задач для асинхронного выполнения
2. **Docker**: изоляция выполняемого кода
3. **Load Balancer**: несколько инстансов сервера
4. **Redis**: кеширование и очередь

### 6. Сравнение с альтернативами

#### Flask (текущее решение):
```
RAM:       85-200 MB
CPU:       1-10% idle, 15-110% при запросах
Диск:      6-110 MB
Трафик:    ~50 MB/месяц
```

#### FastAPI (альтернатива):
```
RAM:       70-180 MB (немного меньше)
CPU:       1-8% idle, 12-100% при запросах
Преимущества: асинхронность, автодокументация
```

#### Node.js Express (альтернатива):
```
RAM:       60-150 MB (меньше)
CPU:       1-5% idle, 10-80% при запросах
Преимущества: асинхронность, меньше памяти
Недостатки: сложнее выполнять Python код
```

### 8. Мониторинг ресурсов

#### Linux:
```bash
# CPU и RAM в реальном времени
htop

# Только процесс сервера
top -p $(pgrep -f "server.py")

# Использование диска
du -sh desktop_server/

# Размер логов
du -h desktop_server/server.log

# Сетевой трафик (требует nethogs)
sudo nethogs
```

#### Windows:
```
# Диспетчер задач
Ctrl + Shift + Esc → вкладка "Процессы"

# Resource Monitor
resmon.exe
```

#### Python скрипт для мониторинга:
```python
import psutil
import os

pid = os.getpid()
process = psutil.Process(pid)

print(f"CPU: {process.cpu_percent()}%")
print(f"RAM: {process.memory_info().rss / 1024 / 1024:.2f} MB")
print(f"Threads: {process.num_threads()}")
```

### 10. Выводы

**Для домашнего использования:**
- ✅ Очень низкое потребление ресурсов
- ✅ Подходит для любого современного ПК
- ✅ Можно запускать на фоне без заметного влияния

**Минимальные требования (практические):**
- RAM: **100-200 MB** в типичном использовании
- CPU: **2-5%** в среднем, до 100% при выполнении
- Диск: **100-500 MB** включая логи
- Сеть: **<1 MB/день** трафика

**Рекомендуемая система:**
- Любой ПК с Windows 10/11, Linux, macOS
- 4+ GB RAM (для комфортной работы ОС + сервер)
- Современный процессор (последние 5-7 лет)
- SSD желательно (для быстрой работы с временными файлами)

**Итоговая оценка**:
Сервер очень легковесный и не создаст проблем даже на слабых ПК. Основная нагрузка зависит от выполняемых скриптов, а не от самого сервера.
